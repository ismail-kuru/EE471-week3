EE471 - Week 3 - Part 3: Inheritance & Hierarchies

In DVD.checkout(), super().checkout() calls the checkout() method of the parent class MediaItem, so the DVD reuses the original logic (check is_available, set it to False, return "Successful checkout" or "Already out") instead of copying it. The DVD only adds its own extra rule on top: it keeps the returned value, prints "Handle with care: Do not scratch the disc." only when that value is "Successful checkout", and then returns the same value so callers get exactly what MediaItem would have returned. Book and DVD also use super().__init__() so that title, author and is_available are set up in one place. Because the checkout logic lives only in MediaItem, a later change to MediaItem.checkout() (for example adding a due date, a borrower name or a checkout log) is automatically inherited by DVD and every other subclass, with no change to their code; this is the DRY principle and keeps all media types consistent. The downside is that subclasses depend on the parent's behaviour: if the parent's contract changes, for instance if the success message is reworded or checkout() starts returning True/False instead of a string, the DVD's check would silently stop matching and the care reminder would no longer be printed, even though no DVD code was touched. So super() gives reuse and a single source of truth, but changes to the parent class must keep its return contract stable, or the subclasses that rely on it must be updated and re-tested together.
